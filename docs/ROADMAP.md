## 1. 故事大纲

### 1.1 核心设定（统一口径，详见 `docs/research_v22.md` §4.1）
- 一万年前，**落魄剑仙（本名李欠欠）** 作为甲方，委托 **天道**（乙方·三界建筑总承包）建造这个修仙世界，合同价“一万年灵气”，约定竣工验收后付尾款。剑仙一直没验收也没付——**欠了一万年的「世界建造尾款」**。
- 合同写着“甲方无力支付时由担保人承担”，担保人一栏是剑仙随手填的**主角生辰八字**。于是天道成立“讨债司”，**上门讨债**。
- 剑仙告诉主角“是你家祖上欠的”——**他在撒谎**（计划在渡劫篇揭穿）。
- 天道不是纯反派：世界确实是它建的，但偷工减料（灵气管道漏气、天劫外包给雷部常劈错人、东海是没封顶的地基坑）。终局本质是**工程款纠纷**，主角当“竣工验收监理”。
- 基调：搞笑、讨债梗（利滚利、取号排队、申诉三千年、天兵甲想当天兵乙）。

## 5. 团队与交接

### 怎么交接（每次工作都照做）
1. 开工：读 `AGENTS.md` → 本文 → `PROGRESS.md` → 看 `git status`、`git log --oneline -20`、GitHub open issues/PR。工作区可能有别人未提交的改动，**不要覆盖别人的文件**。
2. 在分支上开发（如 `v24-xxx`），**小步提交**，提交信息写清改了什么、为什么。
3. 改动走 **PR**，由奥拉夫或主人审查；推 main = 立即发版给玩家，所以 main 只接收通过门禁的代码。
4. 发版前跑完 `AGENTS.md` §5 的全部门禁（`test/human_olaf.py`、`test/human23.py`、`node test/validate22.js` 必须全过）。
5. **收工前更新 `PROGRESS.md`（逐项勾选、写清卡点和下一步）和本文的状态列/已知问题**，然后提交。
6. 新规格写成文档放 `docs/`（或在本文对应条目里写“规格在哪”），不要只留在聊天记录里。
